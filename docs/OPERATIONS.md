# 運用ループ（常時改善）

このシステムは「動かす → 測る → 直す／広げる → また動かす」を毎日くり返す。

## 毎日の点検（自動化担当が実施）

1. **測る**: `https://antaro3.github.io/retro-sale-bot/stats.json` と最新の Actions ログを確認
   - 追跡数 `tracked`、24時間の価格変動 `priceChanges24h`、値下がり分布 `drops24h`
   - 直近の投稿 `posts7d`（posted / dry / rejected / error）、`candidatesLastRun`
   - ログの `失敗` `429` `致命的エラー` `自動停止` の有無
2. **判断**
   - エラー・停止がある → 最優先で原因を直す
   - 数字が悪い（候補ゼロ、却下が多い、反応が無い） → 判定条件・キーワード・文面を改善
   - 問題なし → 下の「拡張バックログ」から次の1つを実装
3. **反映**: ローカルで `npm test` 全合格 → GitHub へ反映（push で自動実行）→ 実行ログと stats.json で効果を確認
4. **記録**: 下の「改善ログ」に1行追記

## 判断の目安

| 指標 | 悪いサイン | 打ち手 |
| --- | --- | --- |
| 候補数 | 0件が続く | 値下がり基準を下げる／キーワード追加／人気商品の条件を緩める |
| 却下 | 価格変動での却下が多い | 実行間隔を詰める／再取得の扱いを見直す |
| 反応（本番後） | いいね・リポストが0 | 文面・ハッシュタグ・時間帯・カテゴリを入れ替える |
| エラー | 3回連続で自動停止 | 原因修正後に STOP ファイルを消す |
